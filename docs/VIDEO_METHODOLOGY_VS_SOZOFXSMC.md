## Phase 4 — Categorized findings

**A. Already implemented by SozoFXSMC**
- BOS/CHoCH state machine with multi-timeframe confirmation
- Liquidity levels (previous high/low, equal highs/lows with tolerance, session highs/lows) and sweep detection
- PDH/PDL/PWH/PWL as a dedicated feature
- Order Blocks with a validated freshness/quality score (Task 9)
- Displacement detection combining multiple measures via a vote (`min_conditions_met`)
- Session windows (Sydney/Tokyo/London/New York), DST-aware
- Asian-range-to-London sweep as a full strategy (S5) — essentially the video's Asia/London pattern already exists
- Multiple stop-loss and take-profit method families, including partial/scaled exits
- Confluence scoring (ITQS/IOS) — more developed than anything described for the video's approach
- Institutional risk layer (position sizing, loss limits, exposure caps, circuit breaker)

**B. Implemented but differently**
- FVG: we have min-size and expiry; the video's described parameter set additionally includes max-size, required-retracement-depth, and a "must remain unfilled" toggle — same concept, narrower current parameter surface
- Entry confirmation: we anchor to Order Blocks (`ob_touch`, `ob_midpoint`, etc.); the video anchors to FVG retracement depth — same philosophy, different anchor object
- Displacement: we vote across multiple measures simultaneously; the video's reconstruction implies testing each measure somewhat independently before concluding which mattered

**C. Completely new (not present in SozoFXSMC at all)**
- Monte Carlo / randomized-trade-sequence robustness testing (no such module exists anywhere in `src/`)
- Explicit "parameter stability region" search (does X±1 still work?) as a formal, automated pass/fail gate — we have the raw capability (`src/research/sensitivity.py::detect_diminishing_returns`) but not this specific stability-region framing wired into a go/no-go gate
- Large-scale (thousands-of-configurations) combinatorial strategy SEARCH as opposed to a small number of hand-designed strategies (S1-S5) each independently backtested — we have the sweep infrastructure (`grid_sweep`, `coordinate_sweep`) but have never run it at "25,000 configuration" scale
- A formal multiple-testing correction step (Bonferroni/FDR or equivalent) applied to a large strategy search — not present anywhere in `src/research/`

**D. Not sufficiently defined (in the video's reconstruction) to compare or test yet**
- Premium/discount (equilibrium/fibonacci) zones — absent from the reconstruction entirely; not a video finding to test
- Exact sampling method for the 25,000-of-258M search
- Exact ranking/scoring formula across the listed metrics
- Exact robustness-test pass/fail thresholds

**E. Potentially dangerous/overfit if adopted uncritically**
- Directly copying the reported "~52% win rate, ~2:1 R:R" numbers as if they were validated targets for Forex — the reconstruction is explicit that these are illustrative, from a DIFFERENT asset class (NQ/ES futures), under an UNKNOWN cost model, and Forex market microstructure (spread-dominated, session-driven, weekend-gap-prone) is materially different (see `docs/VIDEO_25K_ICT_RESEARCH_METHODOLOGY.md` §21)
- Treating "1.7% of configurations survived" as proof of a real edge without knowing whether the survival filter was a genuine statistical-significance test or merely "was profitable in-sample" — see the statistical audit for why these are very different bars
- Running a 25,000+ configuration search on OUR data without a pre-registered, held-out out-of-sample period is exactly the failure mode the video itself warns against (§24 "avoiding data mining" in the reconstruction) — worth flagging because it would be easy to accidentally reproduce the video's OWN cautionary tale rather than its lesson
