# Telegram Notification Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `NOT CONFIGURED: TelegramNotifier requires bot_token + chat_id ...` (local) | `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` not set in your shell | `export TELEGRAM_BOT_TOKEN=...` / `export TELEGRAM_CHAT_ID=...`, or pass `--token`/`--chat-id` to `scripts/test_telegram.py`. |
| Workflow step fails with the same `NOT CONFIGURED` error | GitHub Actions secrets missing or misnamed | `gh secret list` (see `docs/REQUIRED_GITHUB_SECRETS.md`) — names must be EXACTLY `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`. Re-set them if missing. |
| `SEND FAILED: HTTP Error 401: Unauthorized` | Bot token is wrong, revoked, or has extra whitespace | Regenerate via `@BotFather` → `/mybots` → select bot → "API Token" → "Revoke current token", then update the secret/env var. Check for a trailing newline/space if you copy-pasted it. |
| `SEND FAILED: HTTP Error 400: Bad Request: chat not found` | Chat ID is wrong, or the bot was never messaged / never added to the group | Re-do `docs/TELEGRAM_SETUP_GUIDE.md` §2 — you must message the bot (or add it to the group and have someone message it) at least once before `getUpdates` will show a chat ID. |
| `SEND FAILED: HTTP Error 403: Forbidden: bot was blocked by the user` | You (or the chat) blocked the bot | Unblock it in Telegram, or use a different chat ID. |
| No error, `notify()` returns `True`, but no message arrives | Wrong chat ID pointing at a different chat you don't have open, or Telegram notification settings muted for that chat | Double-check the chat ID against a fresh `getUpdates` call; check the specific chat's notification/mute settings in the Telegram app. |
| `SEND FAILED: <urlopen error timed out>` | Network/firewall blocking `api.telegram.org`, or a transient outage | Retry; if persistent, check outbound HTTPS access to `api.telegram.org:443` from wherever the script is running (GitHub Actions runners have unrestricted outbound internet by default — this is more likely a local/corporate-network issue). |
| Duplicate "Approved Trade Opportunity" alerts for what looks like the same setup | `data/live/notified_opportunities.json` wasn't committed/pushed after a previous run (workflow's git push step failed, or you're testing locally without the same state file) | Check the workflow's "Commit updated dedupe state" step logs. Locally, always pass the SAME `--state-file` across repeated runs if you're testing dedup behavior. |
| Workflow's git push step fails with a permissions error | The `GITHUB_TOKEN` for that run doesn't have write access (repo settings restrict Actions' default token permissions), or `permissions: contents: write` was removed from the workflow | Repo → Settings → Actions → General → "Workflow permissions" must allow "Read and write permissions" for the default `GITHUB_TOKEN`, in addition to the `permissions:` block already present in `.github/workflows/telegram-scan.yml`. |
| Markdown looks broken in the Telegram message (stray `_`/`*`/`` ` ``) | A free-text field (a rejection/approval reason) contained an unescaped Markdown special character | `format_trade_alert_markdown` (`src/live/notifications.py`) already escapes `reason`/`extra` fields via `_md_escape` — if you see this, it likely means a NEW field was added to the message without going through that escaping; route any new free-text field through `_md_escape` too. |
| Local `.env`/`ENV.txt` credentials appear to have leaked into a commit | You committed the file despite `.gitignore` | `git status` should show `ENV.txt`/`.env` as ignored — if they appear in `git diff --cached` anyway, someone force-added them (`git add -f`). Immediately revoke the bot token via BotFather (see the 401 row above) and rotate the GitHub secret; treat the token as compromised, not just "removed from the repo." |
